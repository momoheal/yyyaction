# 《鸭鸭鸭行动》跨平台发行准备

更新日期：2026 年 11 月 24 日

本目录整理 App Store、TapTap 和抖音小游戏的第一轮发行文案、素材选用建议和技术/资质缺口。已确认目标是 App Store 中国大陆与海外地区、普通 Tap 小游戏运行时、抖音小游戏。开发者账号和发行资质状态暂按未办理/待核实处理。账号、版权和资质盘点见 [发行主体与资质清单](./03-账号与资质清单.md)。

## 当前项目状态

- 网页版由 Vite 构建，项目提供 `npm run build`。
- 海外 App Store 所需英文界面已加入简中/英文切换机制，英文构建命令为 `npm run build:en`，输出到 `dist-en/`。目前只完成源码实现，尚未构建和逐屏核验；iOS 原生工程仍未提供。
- 小游戏构建目标目前是微信小游戏：`src/minigame/` 和 `vite.minigame.config.ts` 使用 `wx.*` 能力，构建产物为 `minigame/game.js`。这不是可直接提交的抖音小游戏包。
- 当前仓库未发现 iOS/Xcode 工程、Android 原生工程、IPA 或 APK/AAB 构建产物。因此 App Store 和 TapTap 的安装包路径还需要原生工程或经过适配的应用壳，以及各平台的签名与打包流程。
- 普通 Tap 小游戏与 TapTap H5 游戏是不同发布形态。本计划按普通 Tap 小游戏运行时准备，不按 Android APK 或 H5 托管准备。TapTap 真机小游戏环境没有浏览器 `window`/BOM；当前微信适配器不能直接复用，需要新增 Tap 运行时适配、TapTap 登录以及平台包体构建。TapTap 登录流程涉及服务端凭证兑换，需先决定并准备服务端方案。
- 当前游戏存档为本地数据，微信小游戏代码还包含微信生命周期、触控、存储和激励广告接口。若在 TapTap 继续提供激励广告，需接入 TapTap 支持的广告能力；微信 `wx.createRewardedVideoAd` 不能直接沿用。抖音版本也需要适配 `tt` 运行环境、存档、生命周期、广告和平台提审预检要求。
- `art_assets/screenshots/` 根目录现有 30 张 PNG，已核对均为 1280×720；`art_assets/wechat-avatar.png` 是 144×144。截图可优先用于 TapTap 的实机截图，但头像需重新导出大尺寸商店图标。
- `docs/wechat/03-隐私政策.md` 写明微信本地存储与微信广告处理方式，不能直接作为 iOS 或抖音版本的最终隐私材料。现有用户协议也含微信平台表述，应按最终版本逐条更新。
- TapTap 小游戏内容规范限制现金符号。当前 `src/minigame/ui.ts`、`src/game/game.ts` 和 `src/components/Armory.tsx` 将游戏内金币/物资价值显示为 `¥`。TapTap 版本需评估并改为“金币”“价值”等不带现金符号的游戏内显示；有该符号的商店截图也要重截。
- 仓库 `LICENSE` 将原创内容版权标为 `momoheal`。用户确认自己是权利人或持有授权；权利身份、与 `momoheal` 的对应关系及证据仍需核验，提交前要确认发行主体获得代码、美术、音频和名称在三平台及海外地区的发行权。

## 平台准备路径

### App Store

1. 确认 Apple Developer Program 以个人还是组织加入。个人的法定姓名会显示为卖家；组织账号要求合法实体、授权签约人和 D‑U‑N‑S 编号。
2. 为 iOS 建立可安装、可审核的游戏包，明确横屏适配、存档位置、音频、暂停恢复和用户支持入口。
3. 中国大陆商店要求游戏取得游戏审批号；Apple 要求适用的 ICP 备案信息与 App Store Connect 资料和备案信息一致。海外商店另准备英文商店文案与隐私政策，并按各目标地区规则配置。
4. 发布公开可访问的中文与英文隐私政策 URL，并在 App Store Connect 按实际应用代码和第三方 SDK 填写隐私收集信息。
5. 使用真实 iOS 构建录制商店截图；当前 1280×720 网页截图不满足 iPhone 当前要求的截图尺寸。

### TapTap

1. 按普通 Tap 小游戏准备 TapTap 打包工具生成的 zip 包；不同官方文档对包体上限写有 20 MB 与 60 MB 两种口径，生成包前按开发者工具当前预检确认。
2. 接入 TapTap 登录。当前项目没有账号/服务端；TapTap 登录需要服务端参与凭证兑换，会影响隐私说明与发行架构。若希望同时支持 TapTap 云存档或排行榜，另行确定数据方案。
3. 不内购版本需办理小游戏前置备案；TapTap 一份发布指引写明无内购小游戏无需版号，但另一份小游戏审核规范有更宽泛的版号要求。提交资质前须在当前开发者后台确认该发布形态适用的口径。当前游戏无内购，已有微信广告代码不能直接沿用。
4. 已有的横屏实机截图可以作为第一版截图候选。封面、宣传图、图标与 TapTap 运行时实机录屏仍需准备；复核素材和游戏内文案不含受限的现金符号。

### 抖音小游戏

1. 从当前微信小游戏分支适配出抖音运行版本；当前未找到 `tt.*` API 接入。
2. 接入抖音小游戏必接能力，并通过开发者工具预检。官方当前文档将侧边栏复访列为必接能力，预检会检查相关 API 调用。
3. 完成抖音小游戏 ICP 核准并取得 ICP 核准号后再发布；如没有游戏版号，按开放平台当前的小游戏备案与 ICP 核准路径办理。
4. 按抖音规则准备名称、简介、图标、隐私材料与测试路径；提审时使用测试版在真机复核触控、广告、存档和横屏体验。

## 建议执行顺序

1. 确认个人或组织作为发行主体，并核实 `momoheal` 与该主体之间的代码、美术、音频和名称授权。
2. 加入 Apple Developer Program、完成 TapTap 开发者认证并开通小游戏能力、完成抖音开放平台主体认证。
3. 按地区和发布形态盘点审批号、软件著作权、小游戏前置备案/ICP 核准、名称商标与隐私政策材料。
4. 建立 iOS、TapTap 普通小游戏、抖音小游戏三条构建流程；保留当前网页和微信小游戏版本。
5. 完成平台文案、图标、截图、实机视频与平台专属 UI 适配。
6. 在各平台测试环境和真机完成提审前自查，再提交审核。
